# Пакетная обработка с сохранением прогресса

`timetk-batch` выполняет явно согласованный сценарий без вызовов модели.
Используйте его там, где массовые действия разрешены участниками и администрацией.
Поддерживаются macOS и Linux; секреты читаются из обычного хранилища профиля.

## Подготовка

```bash
uv sync --locked --no-editable --all-extras --reinstall-package time-toolkit
timetk-batch plan --profile university \
  --state "$HOME/Downloads/Time Toolkit/example-batch.sqlite" \
  --folder "New channels" --emoji approved_test_emoji --limit 200
```

Для обработки только публичных каналов добавьте `--channel-type O`. Параметр
можно повторять для нескольких типов; без него выбираются O/P/D/G. Типы фиксируются
в подтверждаемом плане и ещё раз проверяются перед чтением сообщений каждого канала.
Канал, который стал приватным после подготовки публичного плана, пропускается с ошибкой.

Для ограниченного теста укажите конкретные ID повторяющимся `--channel CHANNEL_ID`.
Пилотный план содержит только эти каналы; ID не могут добавляться при запуске.

Этот этап выполняет только GET-запросы: проверяет emoji, читает публичный каталог,
членство аккаунта и настройки папок. Выбираются непустые публичные каналы,
приватные каналы аккаунта и его личные/групповые беседы. BSc/MSc не исключаются.
Чужие приватные беседы не доступны. Пустота определяется `total_msg_count`,
а окончательный набор ID сообщений читается при запуске. План не читает тексты
сообщений и не вступает в каналы.

Рядом с SQLite сохраняется `.plan.md` с полным списком каналов, новой папкой,
лимитом сообщений, реакцией, `run_id` и `approval_digest`. Существующие файлы
плана не перезаписываются. Уже существующее имя новой папки получает суффикс;
имя фиксируется до согласования.

## Подтверждение и запуск

После проверки и явного согласования всего плана передайте оба точных значения:

```bash
timetk-batch apply \
  --state "$HOME/Downloads/Time Toolkit/example-batch.sqlite" \
  --approve-run EXACT_RUN_ID --confirm-plan EXACT_APPROVAL_DIGEST \
  --workers 4 --requests-per-second 8
```

Профиль `readonly` запрещает запуск. `approval` допускает этот явно подтверждённый
план; политика профиля не меняется. Значения подтверждают весь перечисленный
пакет, поэтому агент должен согласовать пакет целиком, а не считать согласованием
разрешение на чтение или техническую доступность реакции.

До записи проверяются аккаунт, сервер, emoji, лимит, исходное членство, имена
папок и точный список ID из подписанного хешем плана. Нельзя запустить два
экземпляра одного пакета одновременно.

Последовательность:

1. Вступить в один выбранный публичный канал вне исходного членства.
2. Найти предусмотренную планом папку или создать её, если ещё нет.
3. Сразу перенести этот канал в папку, сохраняя настройки остальных папок,
   и только после успешного переноса переходить к следующему вступлению.
   Ошибка переноса останавливает дальнейшие вступления; повторный запуск
   сначала завершает перенос уже присоединённого канала.
4. Получить до `limit` последних доступных сообщений каждого выбранного канала
   и беседы, включая ответы. В SQLite сохраняются только ID, состояние реакции
   и технические статусы; содержимое сообщений не сохраняется и модели не передаётся.
5. Проверить уже существующие реакции и добавить отсутствующие с ограничением
   частоты запросов. Уже имевшиеся реакции этого аккаунта пропускаются.

При остановке повторите ту же `apply`-команду. Исходное членство и список
сообщений остаются фиксированными; завершённые операции пропускаются. Для
незавершённой попытки перед повтором проверяется фактическая реакция на сервере.
Ошибки авторизации и сети останавливают обработку с сохранением прогресса;
отказы в отдельных каналах/сообщениях сохраняются в базе и не выдаются за успех.
Постоянно отказанные сообщения имеют статус `failed` и автоматически не повторяются.

## Статус

```bash
timetk-batch status --state "$HOME/Downloads/Time Toolkit/example-batch.sqlite"
```

Команда читает только локальный SQLite и не обращается к Time или Keychain.
Секретов в SQLite нет; файл создаётся с правами `0600`. Снимок sidebar перед
изменениями сохранён локально в `sidebar_before`. Автоматического выхода из
каналов, удаления папок и восстановления расположения нет.
